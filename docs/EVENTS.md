# Events

A **mechanic** is a kind of wrong thing the engine knows how to do, written in Go
(`internal/mech`) and audited. A **beat** is a moment in the story that uses a
mechanic with specific text (`story/act1/beats.txt`). Story files can only use these
mechanics and the engine's template variables, so a story is data and never code.

Every mechanic has:

- a **trigger**: what has to have just happened
- a **probe**: whether this shell can show it, from the capability bits the hook sends
- a **weight**: how much a rare trigger boosts the chance of firing
- a **cleanup**: what gets restored, and when

`tenant doctor` shows each shell's capabilities without spoilers.

## Catalogue

| Mechanic | The player sees | Trigger | Needs |
|---|---|---|---|
| `ls.phantom` | One more entry after `ls`, gone next time | `ls` with no paths, exit 0, under `$HOME` | nothing |
| `prompt.glyph` | The directory in the prompt has one letter changed, once | any opportunity | the prompt shows the cwd through a token |
| `history.ghost` | Pressing Up shows a command you never typed, once | any opportunity | Up bound to a plain history function |
| `motd.lastlogin` | A new shell opens with a "Last login" line that knows where you were | first prompt of a shell | nothing |
| `clear.residue` | One faint line survives `clear` | `clear` | nothing |
| `notfound.remark` | A typo gets one more line than usual | a command not found | the handler is wrapped |
| `title.whisper` | The window title changes for one prompt | any opportunity | a terminal that takes titles |
| `prompt.time` | A time appears at the right of the prompt, once | any opportunity | bash: single-line `PS1`; zsh: empty `RPROMPT` |

The finale and the epilogue aren't scheduled mechanics. They are covered in
[STORY](STORY.md#the-finale).

## Details

### ls.phantom

tenant never wraps `ls`. When `ls` has finished, the prompt hook prints one more line
that looks like more output. The name gets its `LS_COLORS` colour if the `ls` was
coloured. In long format it's a row with `$USER`, size 0, and a story time. The
shape comes from the hook, which expands one level of alias, so Arch's `ls
--color=auto` works. It is skipped (`ls:x`) for paths, pipes, `-R`, `-d`, `--icons`,
and `lsd`. The name is either written into the story or a real name from another
directory you visited (`{{names.elsewhere}}`).

### prompt.glyph

The binary picks a lowercase vowel in the directory's last component (never its first
letter) and sends `glyph <offset from end> <from> <to>`. The vowel shifts `a↔e`, `o↔u`,
`i→e`, so `rarepulls` becomes `rarepolls`. The hook checks the letter, builds the
new path, and points the prompt at a variable holding it:

- **bash:** `\w` and `\W` in `PS1` become `${_tenant_pwd}` and `${_tenant_pwdb}`,
  which `promptvars` expands at display time. The path itself never goes through
  prompt expansion.
- **zsh:** `%~ %/ %d` and `%1~ %c %C %.` are replaced. With `PROMPT_SUBST` it's a
  variable reference; otherwise literal text. `%` is escaped either way, and `!` is
  escaped under `PROMPT_BANG`.

The prompt is restored at the next prompt if nothing else has rebuilt it. Prompts that
are generated by a command each time (starship, powerlevel10k) don't have the token,
so the probe fails and the beat's fallback is used instead.

### history.ghost

It is armed at a prompt and consumed by the next press of Up.

- **bash:** `bind -x` binds `\e[A` and `\eOA` to a function that sets
  `READLINE_LINE` from `$(tenant _ghost)`, then rebinds the readline function Up had
  (`previous-history`, `history-search-backward` or
  `history-substring-search-backward`). It is skipped for Up keys that already use
  `bind -x` (atuin, mcfly), for vi mode and for ble.sh.
- **zsh:** a zle widget sets `BUFFER` from `$(tenant _ghost)`, then rebinds the
  previous widget. The probe only accepts well-known history widgets.

Each of the two Up keys (`\e[A` and `\eOA`) is probed and restored separately, and
only borrowed if its function is known. If there turns out to be nothing to show,
the press behaves like a plain Up.

It never uses `history -s` or `print -s`, which would reach `$HISTFILE`. The
integration tests check the history file afterwards.

**A ghost is one Enter away from running**, so the text must pass
`mech.HarmlessCommand`: `cd`, `ls`, `pwd`, `true` or `tenant`; arguments made only of
`[A-Za-z0-9._+/~@:,=-]`; and an optional ` # comment` in plain words. That rules out
anything a directory name could smuggle in (`$(…)`, backticks, quotes, `;`, `|`,
globs), and `!` history expansion. Text that fails is skipped, so the beat uses its
next alternative.

### motd.lastlogin

It prints `Last login: Thu Oct  8 23:41:07 2026 on pts/3 from ~/code/rarepulls` on
the first prompt of a new shell, never while the rc file is loading. The time is the
last late-night visit (21:00 to 04:00) before this sitting, if there is one. The
terminal name is real.

### clear.residue

After `clear`, one faint line is printed at the top of the empty screen.

### notfound.remark

The hook runs your existing handler first (pkgfile, for example), unchanged, or
prints the shell's usual message. Then it asks tenant, which may add one faint line.
`{{typo.meant}}` is the command you've used at least three times that is within two
edits of the typo.

### title.whisper

It pushes the current title onto the terminal's title stack (`CSI 22;0 t`), sets a
new one with OSC 2, and pops it at the next prompt (`CSI 23;0 t`). Terminals without
a title stack keep the new title until something else sets one. It only fires when
stderr is a terminal and `TERM` is a known emulator.

### prompt.time

A short story time appears right-aligned for one prompt. In bash it's a zero-width
`\[…\]` prefix that pads to `COLUMNS` and returns the cursor. In zsh it's `RPROMPT`.

## Writing a new mechanic

Add a type to `internal/mech/mechanics.go` and register it in `init`:

```go
type Mechanic interface {
    ID() string
    Probe(e *Env) bool      // can this shell show it?
    Triggered(e *Env) bool  // did the right thing just happen?
    Weight() float64        // boost for rare triggers
    NeedsText() bool
    Fire(e *Env, text string) (Effect, bool)
}
```

An `Effect` holds text for the terminal (`Say`, which must be sanitised with
`term.Clean`), protocol actions (`Acts`), and hand-offs (`Ghost`, `Time`). A mechanic
can't write shell code and can't touch the filesystem. If it needs a new protocol
verb, add it to `shell.Verbs` and to **both** hook scripts, and extend the
integration test.
